# 微信小程序发布指南

## 发布前检查清单

### 1. 代码准备
- [ ] 确保所有功能已测试通过
- [ ] 确保所有 TypeScript 文件已编译为 JavaScript (`npm run build:miniprogram`)
- [ ] 检查是否有编译错误或警告
- [ ] 确保所有页面配置文件（`.json`）都存在

### 2. 配置检查
- [ ] 确认 `app.json` 中的页面路径正确
- [ ] 确认 `project.config.json` 中的 `appid` 正确：`wxe3af85edd5fae27f`
- [ ] 确认 `apps/miniprogram/config.ts` 已正确生成（包含 `API_BASE_URL` 和 `APP_ID`）
- [ ] 确认服务器域名已在微信公众平台配置

### 3. 服务器域名配置
在微信公众平台（https://mp.weixin.qq.com）配置：

**开发 → 开发管理 → 开发设置 → 服务器域名**

需要配置的域名：
- **request合法域名**：添加你的 API 域名（如：`https://preview.iamsmart.top` 或 `https://www.iamsmart.top`）
- **uploadFile合法域名**：（如果需要上传文件）
- **downloadFile合法域名**：（如果需要下载文件）

### 4. 版本号管理
- 小程序版本号格式：`主版本号.次版本号.修订号`（如：`1.0.0`）
- 在微信开发者工具中设置版本号

## 发布步骤

### 步骤 1：在微信开发者工具中上传代码

1. 打开微信开发者工具
2. 确保项目已正确打开（`apps/miniprogram` 目录）
3. 点击工具栏的 **"上传"** 按钮
4. 填写版本号和项目备注：
   - **版本号**：如 `1.0.0`
   - **项目备注**：描述本次更新的内容
5. 点击 **"上传"** 完成代码上传

### 步骤 2：在微信公众平台提交审核

1. 登录微信公众平台（https://mp.weixin.qq.com）
2. 进入 **版本管理** → **开发版本**
3. 找到刚上传的版本，点击 **"提交审核"**
4. 填写审核信息：
   - **版本描述**：简要说明本次更新的功能和改进
   - **测试账号**：（如果需要）提供测试账号和密码
   - **类目**：选择小程序所属类目（如：教育 → 在线教育）
   - **标签**：添加相关标签
5. 提交审核

### 步骤 3：等待审核

- 审核时间通常为 1-7 个工作日
- 可以在 **版本管理** → **审核版本** 中查看审核状态
- 如果审核被拒，查看拒绝原因并修改后重新提交

### 步骤 4：发布上线

审核通过后：
1. 进入 **版本管理** → **审核版本**
2. 找到审核通过的版本
3. 点击 **"发布"** 按钮
4. 确认发布，小程序即可正式上线

## 重要注意事项

### 环境变量配置

确保生产环境的服务器已配置以下环境变量：
- `WECHAT_MINIPROGRAM_APP_ID`：小程序 AppID
- `WECHAT_MINIPROGRAM_APP_SECRET`：小程序 AppSecret
- `NEXT_PUBLIC_APP_ORIGIN`：API 基础地址（用于生成 `apps/miniprogram/config.ts`）

### 域名配置

- 确保 API 域名已添加到微信公众平台的服务器域名白名单
- 如果使用 HTTPS，确保证书有效
- 域名必须已备案（如果是国内服务器）

### 代码编译

发布前务必运行：
```bash
npm run build:miniprogram-config  # 生成 config.ts
npm run build:miniprogram          # 编译 TypeScript
```

### 测试建议

发布前建议：
1. 在微信开发者工具中测试所有功能
2. 使用真机预览测试（扫描二维码）
3. 测试不同网络环境下的表现
4. 测试登录、数据加载、设置等功能

## 常见问题

### Q: 上传代码时提示"代码包大小超过限制"
A: 检查是否有不必要的文件，确保 `.gitignore` 正确配置，排除 `node_modules` 等

### Q: 审核被拒，提示"功能不完整"
A: 确保所有页面都能正常访问，没有空白页面或错误页面

### Q: 审核被拒，提示"涉及用户隐私"
A: 检查是否在隐私政策中说明了数据收集和使用方式

### Q: 小程序无法访问 API
A: 检查服务器域名是否已配置，API 地址是否正确

## 后续维护

- 每次更新功能后，重复上述发布流程
- 建议保持版本号的语义化（如：1.0.0 → 1.0.1 → 1.1.0）
- 记录每次版本的更新内容，便于用户了解新功能
